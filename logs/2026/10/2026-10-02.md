# 2026-10-02

## 20:19 · 모바일 주문 앱 구조 분석 과제

`UX/UI` · `IA` · `User Flow` · `Wireframe` · `Study`

상용 주문형 모바일 앱의 구조를 뜯어보며 정보 구조, 주문 흐름, 화면 구성의 관계를 정리했다. 이후 실제 화면 하나를 골라 제한 시간 안에 핵심 구조만 남기는 와이어프레임 실습을 진행했다.

### 과제 범위

- 앱의 주요 기능을 상위 카테고리 기준으로 분류해 IA 작성
- 주문 기능을 중심으로 사용자가 완료까지 거치는 단계를 플로우차트로 정리
- 실제 화면 한 개를 선택해 약 20분 동안 Low-fi Wireframe 제작

### IA 정리

앱 전체를 여러 상위 영역으로 나눈 뒤 각 영역의 핵심 기능을 하위 구조로 배치했다.

- 홈: 프로모션, 배너, 퀵 메뉴, 브랜드 소식
- 결제: 결제수단 선택·등록·관리, 쿠폰/상품권, 바코드 결제
- 주문: 매장 선택/검색, 메뉴 탐색, 옵션 선택, 장바구니, 주문/결제
- 쇼핑: 프로모션, 상품 탐색, 카테고리, 상품 상세, 장바구니, 구매/결제
- 기타: 계정 관리, 설정, 영수증, 고객지원

### 주문 플로우차트

주문 과정을 실제 사용 순서 기준으로 단순화했다.

`앱 실행 → 팝업 닫기 → 주문 진입 → 매장 선택 → 메뉴 탐색 → 메뉴 선택 → 옵션 선택 → 장바구니 → 주문/결제 → 주문 완료`

기능 목록을 나열하는 IA와 달리, 플로우차트에서는 사용자의 행동 순서와 완료 지점을 중심으로 구조를 다시 보게 됐다.

### 20분 와이어프레임

음료 옵션 선택 화면을 골라 세부 스타일을 제거하고 정보 위계와 인터랙션 구조만 빠르게 재구성했다.

핵심 구성:
- 상품명
- 용량/사이즈 선택
- 선택 상태
- 친환경 옵션
- 추가 옵션 아코디언
- 수량
- 가격
- 장바구니 / 주문하기 CTA

### 학습 포인트

- IA는 서비스의 기능을 구조적으로 분류하는 작업이고, Flowchart는 특정 목표를 달성하는 사용자의 이동 순서를 보여주는 작업이라는 차이를 실습으로 확인했다.
- 실제 UI를 와이어프레임으로 다시 그리면 색상·폰트보다 정보의 우선순위와 컴포넌트 역할을 먼저 보게 된다.
- 제한 시간을 두고 작업하면 완성도를 높이기보다 화면을 구성하는 핵심 정보와 액션을 빠르게 추출하는 연습이 된다.
