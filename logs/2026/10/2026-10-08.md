# 2026-10-08

## 프로덕트 디자인 베이스캠프 3회차 — UX Problem Report

**Tags:** Product Design, UX Research, Problem Definition, User Observation

### 학습 주제

실제 서비스 사용 과정에서 관찰한 행동을 바탕으로 Fact와 Interpretation을 구분하고, 문제 후보를 도출한 뒤 To-Know와 우선순위를 정리해 UX Problem Report로 연결했다.

### 실습

음악 스트리밍 서비스에서 **한 곡을 재생목록 A와 B에 저장하기**를 Task로 설정해 저장 플로우를 관찰했다.

- 동일한 '재생목록에 추가' 행동에서 재생목록 선택 화면이 나타나는 경우와 특정 목록에 자동 저장되는 경우가 관찰됐다.
- 이미 저장된 곡을 다른 재생목록에도 추가하려 할 때 중복 안내 후 저장 플로우가 종료됐다.
- 사용자는 다른 재생목록에 저장하기 위해 동일한 저장 과정을 다시 수행해야 했다.
- 정상적인 저장은 약 3회의 탭으로 완료됐지만, 의도하지 않은 자동 저장을 삭제하고 다시 저장하는 경우 총 10회의 탭과 추가 스크롤이 발생했다.

### 문제 후보

1. 사용자가 재생목록을 선택하기 전에 자동 저장되어 의도와 다른 위치에 곡이 저장될 수 있다.
2. 동일한 저장 액션에서 서로 다른 플로우가 나타나 다음 결과를 예측하기 어렵다.
3. 이미 저장된 곡을 다른 재생목록에도 추가하려 할 때 중복 안내 후 플로우가 종료되어 동일한 저장 행동을 반복해야 한다.

### 우선 문제

세 번째 문제를 우선 문제로 선정했다.

중복 안내 이후 저장 흐름이 끊기면서 한 곡을 여러 재생목록에 저장하는 Task가 중간에 종료되고 불필요한 반복 행동이 발생하기 때문이다. 발생 빈도는 추가 확인이 필요하지만, 발생 시 사용자의 목표 달성에 직접적인 영향을 준다고 판단했다.

### To-Know

- 한 곡을 여러 재생목록에 저장하는 행동은 얼마나 자주 발생하는가?
- 중복 안내가 나타났을 때 사용자는 다음 단계로 어떤 행동을 기대하는가?
- 사용자는 중복 안내 이후 다른 재생목록을 바로 선택할 수 있을 것이라고 예상하는가?
- 동일한 저장 액션에서 자동 저장과 재생목록 선택 중 어떤 방식을 기대하는가?
- 플로우 종료가 반복 행동이나 저장 포기로 이어지는가?

### 개선 방향

이미 저장된 곡을 다른 재생목록에도 추가하려는 사용자가 저장 과정을 처음부터 반복하지 않고, 현재 흐름 안에서 다음 저장 행동을 이어갈 수 있도록 개선하는 방향으로 정리했다.

### Learning Point

문제를 발견했을 때 바로 UI 해결안을 만드는 대신, 관찰된 행동과 해석을 분리하고 정량적인 Evidence를 남기면 문제의 영향도를 더 명확하게 설명할 수 있다. 또한 동일한 기능이라도 시스템의 결과가 일관되지 않으면 사용자의 예측 가능성과 Task 흐름에 영향을 줄 수 있다는 점을 확인했다.
