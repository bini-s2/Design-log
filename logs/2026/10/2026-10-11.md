## Japanese Sound Search — Context-first pipeline rebuild

### 작업

- 한글로 기억한 일본어 발음을 단어 단위로 먼저 쪼개던 검색 흐름을 전체 문맥 우선 구조로 변경했다.
- 일반 공백은 더 이상 독립 검색의 기준으로 사용하지 않고, 명시적인 구분자가 있을 때만 여러 표현으로 나눈다.
- 사전·IME·자동완성은 후보 생성 근거로 사용하고, 애매한 검색은 LLM 문맥 resolver가 전체 표현 단위로 재판단하도록 구성했다.
- 모델 결과도 발음 전체 일치, 일본어 표기, 사전 또는 문법 구조를 다시 검증한 뒤 노출한다.
- 고확신 결과가 검증되면 낮은 품질의 fuzzy 후보를 함께 보여주지 않도록 랭킹 정책을 변경했다.
- 후보 화면에 문맥 검증 상태를 구분하는 UI를 추가했다.

### 배운 점

- 검색 결과를 많이 만드는 것보다 후보 생성과 후보 검증을 별도 단계로 분리하는 것이 중요했다.
- 규칙 기반 필터만 강화하면 오탐을 줄이는 대신 정답 recall까지 떨어질 수 있어, 의미 판단과 사실 검증을 다른 레이어로 분리해야 한다.
- AI 검색에서도 모델 출력을 그대로 노출하기보다 deterministic evidence로 재검증하는 구조가 필요하다.


### 추가 개선 — 검색 런타임 안정화

- Vercel 배포 환경에서 AI Gateway 인증 토큰을 직접 환경변수로 읽던 방식을 런타임 OIDC helper 방식으로 수정했다.
- AI 호출 실패 시에도 검색이 0건으로 무너지는 문제를 막기 위해 deterministic 발음·문맥 복원 fallback을 추가했다.
- 장음 누락과 긴 표현의 1자음 오청취를 회귀 테스트로 고정해 같은 문제가 다시 생기면 빌드 단계에서 잡히도록 했다.
- 최신 Production 빌드가 회귀 테스트를 통과하고 READY 상태인지 확인했다.
