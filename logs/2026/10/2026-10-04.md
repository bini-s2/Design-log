`UX/UI` · `Problem Solving` · `Case Study` · `Study`

대중교통 이용자의 비용 부담과 제도 이해 부담을 줄이는 교통비 환급 제도를 문제 해결 사례로 선정하고, 사용자·문제·해결 방식·UX 장점·개선 아이디어 기준으로 정리했다.

### 분석 내용

- 반복적으로 대중교통을 이용하는 사용자를 주요 사용자로 정의
- 이용 금액에 따라 정률형과 정액형 중 더 유리한 방식이 적용되는 구조 확인
- 월 80,000원 이용 예시에서 정률형 환급과 정액형 환급을 비교해 실제 부담 금액을 계산
- 정책명과 조건보다 사용자가 실제로 받는 혜택을 먼저 이해할 수 있도록 정보 표현 방식 검토

### 개선 아이디어

앱 첫 화면에서 이번 달 이용금액, 예상 환급액, 실제 부담액을 함께 보여주는 방식을 제안했다. 사용자가 제도 구조를 먼저 학습하지 않아도 현재 받을 수 있는 혜택을 바로 확인하도록 정보 우선순위를 조정하는 방향이다.

### 학습 포인트

- 제도나 정책도 사용자의 행동과 판단 부담을 줄이는 관점에서 UX 사례로 분석할 수 있다.
- 혜택 구조가 복잡할수록 정책명보다 사용자가 실제로 알고 싶어 하는 금액과 상태를 먼저 보여주는 것이 중요하다.

## 15:05 · 음악 스트리밍 앱 구조 분석 과제

`UX/UI` · `IA` · `Flowchart` · `Wireframe` · `Study`

자주 사용하는 음악 스트리밍 앱을 대상으로 정보 구조, 주요 사용 흐름, 홈 화면 구조를 분석했다. 화면에 보이는 기능을 그대로 나열하는 데서 끝내지 않고, 기능을 목적과 성격에 따라 묶어 서비스 구조를 정리했다.

### IA

- 홈 영역을 추천, 탐색, 개인화 성격으로 구분해 하위 콘텐츠를 정리
- 숏폼 음악 탐색, 검색·둘러보기, 보관함 영역의 주요 기능을 계층화
- 화면의 버튼이나 컨트롤보다 사용자가 접근하는 정보와 기능의 구조를 중심으로 구성

### Flowchart

- 앱 실행 후 이용 목적을 빠르게 듣기와 음악 탐색으로 나누어 대표 사용 흐름을 설계
- 빠르게 듣기 흐름은 빠른 선곡 → 음악 재생 → 계속 듣기 여부로 구성
- 음악 탐색 흐름은 검색 → 아티스트 탐색 → 인기곡 재생 → 선호 여부 판단 → 저장 또는 다른 곡 탐색으로 구성
- 다른 곡을 선택한 뒤 다시 선호 여부를 판단하도록 반복 흐름을 연결

### Wireframe

실제 홈 화면을 참고해 컬러와 이미지 디테일을 제거하고 정보 위계와 레이아웃만 남긴 Low-fi Wireframe을 제작했다. 상단 탐색 영역, 빠른 선곡 카드, 최신 음악 영역, 미니 플레이어, 하단 내비게이션의 구조를 중심으로 재구성했다.

### 학습 포인트

- IA는 서비스 전체의 정보와 기능이 어디에 속하는지 정리하는 작업이다.
- Flowchart는 특정 목표를 수행하는 사용자의 행동과 선택, 반복 흐름을 보여준다.
- Wireframe은 앞에서 정리한 구조와 흐름을 실제 화면 배치로 옮기는 단계다.
- 화면을 그대로 복제하기보다 기능의 역할과 정보 위계를 남기는 것이 중요하다.
