# 2026-10-22 — AI 포트폴리오 프로토타입 회고와 Framer 재구축 방향

**분야:** Web Design / UX/UI / Portfolio / Framer / AI-assisted Design

## Overview

AI 웹사이트 빌더로 개인 포트폴리오의 레이아웃과 인터랙션을 빠르게 구현하고 여러 시안을 발전시켰다. 시각적 표현과 기능의 완성도는 높아졌지만, 작업을 진행할수록 사이트의 목적과 정보 전달 구조가 흐려지는 문제를 발견했다. 이전에 직접 Framer로 사이트를 제작할 때와 비교하며 디자인 프로세스를 회고했다.

## 관찰한 문제

- 인터랙션과 시각적 효과가 매력적으로 구현되면 명확한 필요성 검토 없이 기능을 추가하게 됐다.
- 표현 요소가 증가하면서 방문자가 무엇을 이해해야 하는지, 프로젝트를 어떻게 탐색해야 하는지에 대한 기준이 약해졌다.
- 사전 러프 스케치와 디자인 의도를 정하지 않고 제작을 시작해, 여러 시안이 모두 매력적으로 느껴지면서 방향이 자주 바뀌었다.
- 구현의 완성도와 설계의 완성도는 구분해서 평가해야 한다는 점을 체감했다.

## 이전 프로젝트와의 비교

- **기존 Framer 제작:** 목적과 러프 스케치를 먼저 정하고 레이아웃·모션을 구현해 선택의 근거가 비교적 명확했다.
- **이번 AI 기반 제작:** 결과물을 빠르게 생성·수정하는 과정에서 탐색의 폭은 넓어졌지만, 방향을 확정할 디자인 기준이 부족했다.
- AI 도구의 강점은 빠른 시안 탐색과 구현이며, 디자이너는 기능과 표현을 왜 채택하는지 판단해야 함을 확인했다.

## 결정한 방향

현재 AI 빌더에서 만든 결과물을 최종 디자인 그대로 이식하기보다 **시안·프로토타입·구조 레퍼런스**로 활용하고, Framer에서 설계 의도를 재정립해 새로 구축하는 방향을 검토한다.

- 가져올 것: 유용한 정보 구조, 페이지 뼈대, 프로젝트 분류, 콘텐츠, 필요한 기능 아이디어
- 다시 설계할 것: 정보 위계, 비주얼 시스템, 카드·섹션 구성, 모션의 목적과 강도, 반응형 경험
- 무조건 보존하지 않을 것: 멋있다는 이유만으로 추가한 장식적 인터랙션과 불필요한 기능

## 다음 작업

1. 포트폴리오의 목적, 주요 방문자, 핵심 전달 메시지를 1장짜리 디자인 브리프로 정리한다.
2. 기존 시안의 섹션과 기능을 유지·수정·제거로 분류한다.
3. 러프 스케치와 정보 구조를 확정한다.
4. Framer에서 핵심 레이아웃을 구축한 뒤 의도에 맞는 인터랙션을 추가한다.
5. 프로젝트 탐색과 상세 페이지 이해도를 기준으로 검수한다.

## 배운 점

> **'만들 수 있는 것'과 '만들어야 하는 것'은 다르다.**

AI로 구현 비용이 낮아질수록, 시각적 완성도에 이끌려 기능을 늘리기 쉬워진다. 결과물이 화려한지보다 어떤 문제를 해결하고 무엇을 전달하는지 판단할 기준을 먼저 세우는 것이 중요하다.

*이 기록은 설계 방향을 정리한 회고이며, Framer 재구축이 완료되었다는 의미는 아니다.*

## 추가 회고 — AI 작업에서의 몰입과 생산성

AI에 작업을 맡겼을 때 집중력이 떨어지는 경험도 관찰했다. 결과물을 기다리는 동안 주의가 다른 곳으로 이동했고, 완성된 시안을 평가하는 일이 늘면서 직접 설계·구현할 때의 몰입감이 감소했다. 이는 AI 사용 전반의 효과라기보다 이번 작업 방식에서 체감한 변화다.

반면 AI의 실질적인 효용도 두 가지로 명확해졌다.

1. **아이디어의 빠른 시각화:** 머릿속에 있던 레이아웃이나 시안을 짧은 시간 안에 화면으로 확인하고 대안을 비교할 수 있었다.
2. **구현 가능성 탐색:** 상상한 인터랙션이 어느 정도까지 실제 동작하는 형태로 구현되는지 프로토타입으로 시험할 수 있었다. 단, 시연이 가능하다는 사실과 최종 환경에서 안정적으로 운영할 수 있다는 사실은 구분해야 한다.

### 다음 작업에 적용할 프로세스

**직접 목적·러프 스케치 정의 → AI로 시안·인터랙션 프로토타이핑 → 직접 채택·수정·제거 판단 → Framer에서 최종 설계·구현·QA**

AI의 역할을 전체 디자인의 의사결정자로 두기보다, 아이디어를 빠르게 검증하는 도구로 제한하는 방식이 현재 작업 스타일에 더 적합하다고 판단했다.

> **AI는 디자인을 대신 결정할 때보다, 내가 상상한 디자인을 빠르게 확인하고 실험하게 해줄 때 더 유용했다.**

## 추가 작업 — 포트폴리오 화면 구성 및 인터랙션 검토

**작업 상태:** Readdy 프로토타입 검토 / Framer 재구축 전

### 현재 프로토타입 구성

배포된 프로토타입과 화면 캡처를 바탕으로 다음 구조를 정리했다.

- **ALL WORKS:** 8개 프로젝트 카드와 ALL / UXUI / BX 필터.
- **프로젝트 소개·상세:** 대형 비주얼, 분할형 화면 연출, 개별 프로젝트의 문제 및 디자인 설명.
- **ABOUT:** 기존 디자인 경력, 작업 관점과 역량을 설명하는 정보 섹션.
- **CONTACT:** 대형 인사 타이포그래피, 문의 폼과 마무리 화면.
- **전역 요소:** 챕터 진행 표시·세로 눈금 내비게이션, 상단 이동 FAB, 전체 화면 메뉴, 코발트 블루 푸터.

### 직접 설계한 인터랙션 아이디어

**상단 이동 FAB**

- 기본은 흰색 원형 버튼.
- 일정 시간 호버·조작이 없으면 불투명도를 낮춰 콘텐츠 집중을 방해하지 않도록 설계.
- 호버 시 코발트 블루로 강조.
- 사용자가 닫으면 화면 가장자리의 TOP 탭 형태로 축소.
- 모바일에서는 가장자리로 밀어 접는 동작을 추가로 검토. 단, 드래그를 모르는 사용자를 위한 명시적 접기·복원 방법도 필요.

**챕터 눈금 내비게이션**

- 작은 세로 눈금에 마우스를 올리면 챕터명을 표시하고 현재 항목을 강조.
- 시각적 눈금의 간격·위치는 그대로 두고 보이지 않는 포인터 클릭 영역만 넓히는 방식을 시도.
- 처음에는 AI가 '호버 범위 확대'를 눈금 사이 간격 확대와 혼동했으나, 반복 피드백 끝에 의도한 동작이 구현된 화면을 확인.
- 각 항목의 실제 클릭 연결, 호버 유지, 모바일 조작은 별도 QA 필요.

### 화면 리뷰에서 발견한 점

- 프로젝트 분류와 카드 그리드는 기존 BX 작업과 UX/UI 경험을 함께 탐색하게 하는 구조로 유용하다.
- 일부 프로젝트 썸네일은 전반적으로 어두워서 식별성이 약할 수 있다.
- 프로젝트 상세에서는 시각적 연출이 강한 만큼, 프로젝트 맥락·문제 정의·판단 근거·결과의 정보 위계를 우선할 필요가 있다.
- ABOUT 및 일부 섹션은 여백과 정보 밀도를 재점검할 필요가 있다.
- 스크린샷만으로는 애니메이션 중간 상태인지 알 수 없어, 가독성이나 인터랙션의 실제 품질을 확정 평가하지 않는다.
