# 2026-10-09

## UX Problem Report 완성 및 AS-IS 화면 정리

**Tags:** UX/UI, UX Research, Problem Definition, AS-IS, Product Design

### 오늘의 작업

음악 스트리밍 앱의 재생목록 저장 플로우를 대상으로 진행한 관찰·분석 내용을 하나의 **UX Problem Report**로 구성하고, 다음 단계에서 사용할 **AS-IS 화면**을 준비했다.

- **Service:** YouTube Music
- **Task:** 한 곡을 재생목록 A와 B에 저장하기
- **분석 구조:** Task → Evidence → Fact → Interpretation → To-Know → 문제 후보 → 우선순위 → 개선 방향
- **AS-IS:** 재생목록 탐색과 곡 저장 과정에 관련된 기존 서비스 화면 3개를 별도로 배치해 정리

### 관찰을 기반으로 한 문제 정의

- 저장 과정에서 재생목록 선택 화면이 나오는 경우와 특정 목록에 자동 저장되는 경우를 관찰했다.
- 이미 저장된 곡을 다른 재생목록에도 추가하려는 과정에서 중복 안내 이후 저장 흐름이 종료되어, 다시 저장 경로에 진입해야 하는 상황을 기록했다.
- 같은 Task에서 발생한 추가 탭·스크롤과 반복 행동을 근거로 문제 후보를 정리했다.
- 여러 문제 후보 중 **저장 흐름 종료로 인한 반복 행동**을 우선 분석 대상으로 선정했다.

### 개선 방향

이미 저장된 곡을 다른 재생목록에 추가하려는 사용자가 처음부터 저장 과정을 반복하지 않고, 현재 흐름에서 다음 저장 행동을 이어갈 수 있도록 하는 방향을 정리했다.

이 단계에서는 구체적인 TO-BE UI를 설계하지 않고 문제 정의에 집중했다.

### 검토 및 보완 포인트

- Interpretation에서 도출한 내용을 **검증이 필요한 문제 가설**로 명확히 표현하기
- 우선순위 근거에 반복 행동뿐 아니라 **Task 완료에 미치는 영향**을 명시하기
- AS-IS 화면에 단계명과 문제가 나타나는 지점을 표시하기
- 관찰한 특정 조건의 동작을 서비스 전체의 확정된 규칙으로 일반화하지 않기

### Learning Point

관찰된 사실과 해석을 구분해 보고서를 작성하고, 사용자 행동의 불필요한 반복이 Task에 어떤 영향을 주는지 근거를 연결하는 연습을 했다. AS-IS 화면은 다음 단계의 AS-IS / TO-BE 분석과 UI 개선안을 위한 기준 자료로 준비했다.

> 이 기록은 작업 과정과 과제 검토 내용을 요약한 것으로, 실제 서비스의 모든 조건에서 동일한 동작이 일어난다고 단정하지 않는다.
