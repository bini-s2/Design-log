### UX Structure

- 온보딩/진단에서 히라가나·가타카나·한자·문법·콘텐츠 어휘·Sound→Script 연결을 분리해 확인하는 구조를 잡았다.

- `Candidate → Expression Result → Deep Dive → Quick Recall → Save / My Expressions → Review`로 이어지는 핵심 학습 루프를 정리했다.

- 복습은 단순 누적량보다 틀렸던 표현, 여러 번 찾은 표현, 문자 연결이 약한 표현을 중심으로 자동 구성하는 방향을 검토했다.
- LISTEN은 콘텐츠 기반 학습 V2, WRITE는 후순위 기능으로 분리했다.

## 일본어 학습 서비스 Master Wireframe 정리

`Product Design` · `UX Research` · `Wireframe` · `AI Workflow`

Figma와 Readdy에서 생성한 여러 와이어프레임 안을 비교하고, 앞서 진행한 시장·경쟁 서비스 조사와 Sound-first 학습자 가설을 기준으로 핵심 UX를 통합했다. Readdy는 Low-fi 구조와 클릭 프로토타입 보강에 활용하고, Figma 안에서 유효했던 후보 비교·문맥 입력 요소를 선별해 반영했다.

### Final Core Flow

- `Home / Sound Search → Candidate Selection(조건부) → Expression Result → Quick Recall / Deep Dive / Save → My Expressions → Review`
- 후보가 1개로 충분히 좁혀지면 Candidate Selection을 건너뛰고 바로 Result로 이동한다.
- Candidate에서는 유사 발음 후보의 의미 차이를 비교하고, 필요할 때만 J-POP·애니·드라마·대화 등 출처와 앞뒤 문맥을 추가해 후보를 재정렬한다.
- Result는 일본어 원문·읽기·자연스러운 뜻을 최우선으로 보여주고, 검색 결과를 짧은 Recall 학습으로 연결한다.
- Deep Dive는 별도 페이지가 아니라 Result 내부의 Progressive Disclosure로 처리하며, 표현 유형에 따라 한자·가타카나·활용·문법 등의 우선순위를 다르게 노출한다.
- Save는 별도 화면 대신 패널/인라인 상태로 처리하고, 앞 단계에서 입력한 출처와 맥락을 재사용한다.
- My Expressions는 카드 그리드보다 Row List 기반 개인 학습 아카이브로 구성한다.
- Review는 무작위 반복보다 Sound→Script 연결 약함, 여러 번 검색, 오래 보지 않음 등 복습 이유를 설명 가능한 형태로 제시한다.

### Prototype / Edge Cases

- 검색 중 Loading
- 후보 없음 / 후보 다수 / AI 판단이 애매한 상태
- 네트워크·API 오류
- 이미 저장된 표현
- 저장 성공/실패
- 복습할 표현이 없는 상태
- Quick Recall 정답/오답에 따른 학습 피드백

### Decision

- Home의 학습 대시보드·랜덤 연습·스트릭 중심 구조는 제외한다.
- 프로토타입용 Stepper와 QA 상태 전환 메뉴는 실제 제품 UI에서는 제거한다.
- Diagnostic Onboarding, LISTEN, WRITE는 현재 핵심 플로우에서 제외하고 후속 검증 기능으로 남긴다.
- 다음 단계는 화면을 더 늘리기보다 Master Wireframe을 고정한 뒤 Primary User Test용 Task와 시나리오를 설계하는 것으로 잡았다.
