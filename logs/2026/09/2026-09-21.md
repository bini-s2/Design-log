# 2026-09-21

## Japanese Sound to Script — 검색 정확도 및 배포 개선

- Readdy 기반 프로토타입을 GitHub `bini-s2/readdy-1ff67b`에 정리하고 Vercel에 배포해 실제 웹에서 테스트할 수 있는 상태로 전환했다.
- 기존 소수 하드코딩 검색에서 벗어나 일본어 사전 검색을 연결해 단어 검색 범위를 크게 확장했다.
- 한글로 들은 일본어 발음을 검색할 때 완전 일치뿐 아니라 발음 유사도, 길이, 장음, 촉음, 유성/무성 자음 차이까지 비교하도록 검색 로직을 보강했다.
- `키미노 → 君の`처럼 대명사 + 조사, 짧은 구문을 일반 사전보다 우선 인식하도록 문법 기반 예외 처리를 추가했다.
- 문장형 입력과 띄어쓰기 없는 입력을 처리하기 위해 소리를 단어·조사·동사 단위로 분절하는 로직을 추가했다.
  - 예: `도코에이코 → どこへ行こう`
  - 예: `히토츠데이 → ひとつでいい`처럼 연속 모음/장음 가능성도 후보로 비교
- 검색 후보는 유사도가 높은 순서로 정렬하고, 첫 후보에 ‘가장 유사’ 표시를 추가했다.
- 발음이 부정확한 경우 ‘혹시 이 표현을 찾으셨나요?’ 형태의 추천과 ‘발음 보정 / 의도 추정’ 상태를 분리해 보여주도록 개선했다.
- 소설명·노래 제목·고유명사 등 학습 목적과 거리가 있는 사전 메타 항목은 일반 표현 후보가 있을 경우 후순위 또는 제외되도록 필터링했다.
- 일본어 원문 아래에 읽기와 한국어식 발음 표기를 함께 제공하도록 결과 UI를 확장했다.
  - 예: `東京フラッシュ / とうきょうフラッシュ / 도쿄 후랏슈`
- Vercel 자동 배포를 통해 GitHub 수정 사항이 실제 서비스에 바로 반영되는 작업 흐름을 구축했다.

### 배운 점

- 이 서비스의 핵심은 ‘정확한 일본어를 아는 사용자’가 아니라 ‘소리만 어렴풋이 기억하는 사용자’를 위한 검색이므로, 사전 검색보다 발음 복원과 문맥 추정 로직이 더 중요하다.
- 단순 fuzzy search만으로는 짧은 구문, 조사, 장음, 띄어쓰기 누락, 외래어 혼합에서 오류가 많이 발생해 문법적 분절과 후보 품질 필터가 함께 필요하다.
- 실제 사용 테스트를 반복하면서 잘못된 후보 사례를 모으고 랭킹 규칙을 개선하는 과정이 검색 UX 품질에 직접 연결된다.
