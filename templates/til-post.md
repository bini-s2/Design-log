# TIL 전용 작성 템플릿

사용자가 "TIL 작성하자"라고 하면 가장 먼저 읽는 규칙. 2026-10-26 사용자가 직접 교정한 TIL 예시를 기준으로 한다. 기존 티스토리 포트폴리오/프로젝트 포스팅과 **다른 글 유형**이다.

## 최우선 구분 — 포트폴리오 글과 달라야 한다

- TIL에는 **프로젝트명 / 역할 / 기간 / 업계 / 기여도** 다섯 줄의 메타 정보를 절대 기본 삽입하지 않는다.
- TIL에는 **Overview / 오버뷰 섹션도 넣지 않는다.** 서두는 제목 아래 자연스러운 1~4개의 문단으로 바로 시작한다.
- 프로젝트·작업노트 글의 포트폴리오 메타 형식은 TIL에 적용하지 않는다.
- 학술 논문, 강의 교안, 보고서, 포트폴리오 케이스 스터디 같은 문체보다 **그날 배운 점과 자기 경험을 연결한 회고**에 중점을 둔다.
- TIL은 나중에 포트폴리오/이력서 작성 시 꺼내 쓸 **학습·실무 경험의 근거 기록**이다. 당시 생각, 작업, 판단, 실제 관찰과 검증 한계를 충실히 남기되 이력서용 성과로 과장하지 않는다.

## 문체와 편집

- 기본 종결: 자연스러운 `~했어요 / ~해요`. 본인이 정리하는 블로그 학습 일지처럼 쓴다.
- 자연스럽게 이어지는 짧거나 중간 길이 문단. 지나친 쪼개기, 개념마다 반복된 요약, 불필요한 교훈·명언을 피한다.
- 사용자가 쓴 표현과 의도를 우선한다. 키워드만 메모한 항목은 1~2문장만 설명한다. 사실·수치·UT 수행 여부 등은 절대 만들어내지 않는다.
- 정량적 성과, 개인 인상, 추론, 미검증 가설은 구분하여 기록한다.
- 제목은 `[카테고리] 직관적인 제목` 형태로 작성한다. 카테고리 분류와 별개로 TIL의 본문 형식은 항상 이 규칙이 우선한다.
- 상위 섹션 `##`, 소제목 `###`, 상위 섹션 사이 `---`. 번호 매기기는 필요한 경우만.
- 티스토리용 초안 작성과 실제 발행, GitHub `/log` 기록은 별개다.

## 기본 구조 (내용에 맞춰 조절)

```markdown
# [UXUI 인사이트] 오늘 배운 주제

오늘은 ...에 대해 공부했어요.
...를 배우면서 예전에 진행했던 작업도 떠올랐어요.

---

## 배운 것 정리/메모

### 배운 개념
정의와 이해한 내용을 간결하게 정리하고, 실제로 궁금했던 점을 기록해요.

### 새롭게 알게 된 용어
짧게 메모했다면 1~2문장만.

---

## 오늘의 활동 또는 경험을 설명하는 제목

### 실제로 고민하거나 수행한 일
구체적인 작업, 판단 이유, 관찰, 한계, 당시 이해를 기록해요.
필요하면 문제 정의 / 설계 / 검증 / 협업으로 나누되 매번 강제하지 않아요.

---

## 느낀 점

오늘 알게 된 것과 이전 경험을 연결해 보고, 부족했던 점이나 앞으로 해보고 싶은 일을 자연스럽게 적어요.
```

## 포트폴리오·이력서로 나중에 발전시키기 위한 기록 원칙

- 학습 일지 안에 실제로 수행한 업무·과제의 문제, 맥락, 선택 이유, 다른 직군과 한 협업, 결과 또는 피드백이 있으면 가능한 한 구체적으로 보존한다.
- 실제 성과와 추정/가설, 본인이 한 일과 다른 사람이 한 일, 검증한 것과 검증하지 못한 것을 구분한다.
- 없는 전환율·효율 개선·정식 UT 등을 넣지 않는다.
- 인사이트를 나중에 포트폴리오로 변환할 수 있게 기록하되, **당장 TIL을 성과 중심 케이스 스터디처럼 바꾸지 않는다.**

## 2026-10-26 사용자 교정본의 특징

- 첫 문단은 '오늘은 프로덕트 디자이너 부트캠프 활동에서...'로 시작해 간단한 학습 맥락을 자연스럽게 풀었다. Overview 제목이나 프로젝트 정보 블록은 없었다.
- `## 배운 것 정리/메모`: KPI와 UT, UX/UI 프로세스, 디자인 엔지니어(두 문장), 취미·관심 직군·관심 기업.
- `## 프로덕트 디자이너의 역량 4가지에 내 경험 정리하기`: 문제 정의, 설계, 검증, 협업을 예전 BX 업무와 연결했다.
- `## 느낀 점`: 검증 역량의 부족함과 협업 관심, 앞으로 배울 점을 회고했다.
- 이 세 개 섹션명은 **해당 글의 예시**로만 참고하며 미래 TIL에 억지로 똑같이 넣지 않는다.

이 문서는 TIL에 대해 `POSTING_RULES.md`의 범용 지침보다 우선한다. 공통 문체는 `WRITING_RULES.md`를 따른다.
